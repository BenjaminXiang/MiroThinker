# Canonical V2 逻辑重建——效果层需求基线

## 1. 产品目标

面向深圳科创生态建立可信、可追溯、可持续更新的知识与对话检索底座。用户能够围绕
教授、企业、论文、专利及其业务关系进行事实查询、语义发现、条件筛选、关系探索和
证据化分析。

本次重建的目标不是复制事故前数据库，也不是针对固定测试答案补数据，而是在可恢复
证据的基础上得到更符合 PRD、质量更高且可持续演进的知识底座。

## 2. 用户可获得的知识效果

### 2.1 四域覆盖

- 教授、企业、论文和专利分别遵循各自 PRD 的收录范围。
- 用户可以获得四域对象的核心事实、必要详情和业务必要关系。
- 对象信息不完整时，只要身份和现有事实可信，仍应在合适的查询路径中可发现，并明确
  信息缺口；不能因为缺少 enrichment 就整体消失。
- 全国性、最新或本地库未覆盖的信息可由实时 Web 证据补充，但不因此无边界扩张本地
  canonical 数据集。

### 2.2 完整关系能力

- 用户可以探索身份/生命周期、机构与角色、学术成果、知识产权、企业人物与业务、
  产品与场景、融资与事件、主题分类、来源与血缘等 PRD 所需关系。
- 关系必须表达真实业务语义，而不是只提供少数固定的跨域跳转。
- 事实关系、可重算的派生关系和会话中的临时关系不会混为一谈。
- 关系探索以多轮渐进方式完成：每轮解决一个明确问题，并引导用户选择下一步，而不是
  一次性展开所有关系。

## 3. 数据可信效果

### 3.1 身份正确与连续

- 同一现实对象不会因名称、格式、来源或历史 ID 不同而重复展示。
- 同名不同对象不会被错误合并。
- 历史错误合并和错误关系可以被纠正。
- 重建后的跨域引用必须解析到正确对象；旧 ID 和历史引用只需作为恢复血缘可追溯，
  不构成新系统的兼容负担。
- 身份变化和人工修正可追溯。

### 3.2 来源、冲突与时间

- 重要实体、字段和关系能够追溯到具体来源、时间和处理过程。
- 不同来源的原始断言均被保留，不因选出当前值而被覆盖或删除。
- 来源冲突经过确定性信息与 LLM 语义判断共同分析；无法可靠裁决时保留冲突并在影响
  回答时披露。
- 用户看到的是当前最合理的信息，同时系统保留必要历史，能够解释信息为什么发生变化。
- 全面性与精准度同等重要：普通不完整和不确定性优先通过排序、标注、补强和审核处理，
  只有明确身份错误、终止合并/拒绝、不可安全展示或完全无可用事实等情况才硬排除。

## 4. 检索与关系探索效果

### 4.1 多种查询都能正确到达数据

- 明确名称、DOI、arXiv ID、专利号等精确查询不会因语义改写而丢失。
- 自然语言主题和同义表达能够召回语义相关对象，而不局限于字面关键词。
- 地域、机构、年份、职称、融资阶段、专利类型等明确条件能够正确筛选。
- 已知关系能够按方向、角色和状态遍历，并保留来源与覆盖说明。
- A–G 继续表达产品行为，但不会把检索锁死在单一固定通道。

### 4.2 查询改写与补检

- 系统理解多轮指代、别名、口语表达和隐含关系意图，并为不同检索来源形成合适表达。
- 原始问题以及精确标识、时间、地域、否定等明确约束不会被改写改变。
- 候选阶段优先保证合理全面，再通过身份去重、证据融合、规则和 LLM 判断提升精准度。
- 首轮证据无法覆盖问题关键部分时，系统可进行有边界的针对性补检；达到预算后如实说明
  未解决部分，不无限搜索或编造答案。

### 4.3 Universal Web augmentation

- 所有信息检索型请求均使用 Web Search 补强时效性、交叉验证和覆盖。
- 越界拒答、纯澄清回复和界面控制指令不需要 Web Search。
- Web 与本地知识共同参与回答，但 Web 命中不自动成为本地 canonical 事实。
- Web 服务失败时，系统仍返回可用的本地结果并说明限制。

## 5. 生成效果

### 5.1 有依据的直接回答

- 回答先解决用户当前问题，再提供必要依据、限制、冲突和下一步探索方向。
- 每个重要事实在系统内部都能映射到本地或本次 Web 证据。
- Web 事实、来源冲突和模型综合判断在用户界面中被清楚区分。
- 本地高可信事实可以通过简洁的卡片或来源入口展示，避免正文被引用淹没。

### 5.2 充分使用 LLM，但不把模型当来源

- LLM 的世界知识用于理解问题、消歧、判断相关性和合理性、比较来源、筛选候选、评估
  证据充分性以及组织最终回答。
- 具体实体、关系、能力、角色、日期和数字等重要事实仍需本地或当前 Web 证据。
- 无法验证但有帮助的内容只能作为明确标注的模型综合判断或推断。
- 对技术实力、市场竞争力、成熟度、专家地位等评价，系统说明评价维度和事实依据，再给
  出带条件和不确定性的综合判断。

### 5.3 渐进式多轮体验

- 每轮只展开当前需要的事实或一段有边界的关系路径。
- 下一步问题根据实际存在且可展示的数据关系生成，而不是通用或虚构的提示。
- 用户选择后才继续探索；实体、结果集、条件和已走路径在会话中保持连续。

## 6. 持续运营效果

### 6.1 数据可以安全持续演进

- 历史恢复、重新采集和增量数据不会直接破坏当前可用版本。
- 每次更新形成内部一致、可验证的候选；只有通过验收的完整版本才成为服务版本。
- 数据库发布内容和向量检索内容来自同一已接受版本，不出现一边更新、一边未更新的状态。
- 上一可用版本可恢复，失败更新不会要求重新从零开始。

### 6.2 查询反馈推动补强

- 无结果、证据不足、频繁依赖 Web、关系缺失、用户反馈和 benchmark badcase 会形成明确
  的知识缺口。
- 知识缺口可以驱动定向重新采集、enrichment、关系补全或检索修正。
- 在线查询不会直接把未经验证的 Web 内容写入正式数据。

### 6.3 恢复证据可重用

- WAL/FPI、Milvus 副本、SQLite/JSONL/XLSX、历史文件和重新采集结果均保留原始证据、
  hash、时间和处理血缘。
- 后续清洗、融合、canonical 和索引结果可以从这些证据重新生成。
- 原始事故库和原 Milvus 在独立批准前保持冻结，不作为重建写入目标。

## 7. 验收效果

- workbook 是种子 case，不是唯一测试集或答案模板。
- 验收覆盖 PRD 问题族、人工确认的真实 badcase、别名/条件/关系/多轮变体，以及持续更新
  的 challenge set。
- 按域和查询路径分别报告 coverage/reach、Recall、Precision、排序、关系、多轮、事实支持、
  回答完整度、Web 来源、数据库/索引一致性、延迟和成本。
- Coverage 与 Precision 分别达标，不能依靠平均分相互抵消。
- 身份串错、无证据的重要事实、断裂引用和数据库/索引版本错配等硬错误在验收范围内为零。
- 已有 PRD 数值指标继续作为下限；其余阈值通过只读 baseline、人工标注和业务风险校准后
  写入正式 spec，实施期间不得降低标准以通过验收。

## 8. 范围边界

- 不把 Canonical V2 扩展成无边界的全国通用知识库。
- 不以生成万字级行业研究报告为一期目标。
- 不要求一次 query 穷尽所有关系。
- 不把向量索引、Web 搜索结果或 LLM 世界知识当作 canonical 事实源。
- 不因恢复目标而复刻旧数据库中的重复、错误关系或过严门控。
- 系统尚未上线，允许为最终效果重构或替换旧 schema、ID、API、检索链、管理流程和测试；
  旧代码形状与内部兼容不是产品目标。
- 本文只定义效果；物理 schema、ID、索引布局和发布编排在后续设计中以这些效果为准。
