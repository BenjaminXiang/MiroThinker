## 0. 30 秒先看这一页

管理台是给你管理这套系统用的后台。你最常做的三件事：

1. **看系统是否正常**：登录后看首页的「系统状态」。
2. **查/改数据**：打开「数据浏览」，搜索企业、论文、专利、教授，点开一条就能看详情或改字段。
3. **看用户问了什么**：打开「访问日志」，按时间或关键词查。

你不需要安装软件，也不需要懂服务器。用浏览器打开上面的地址，登录即可。

**最重要的一条**：「删除」「重置口令」点下去就生效；「日常采集」里的任务可以点「立即运行」；「教授采集源」可以打开 Seed 管理页；「高级操作」「数据导入」不要点；「保存本卡」会改设置，但通常要平台同事重启后才生效。做之前先看清楚，不确定就先问平台同事。

## 1. 登录与退出

### 1.1 第一次登录

1. 用浏览器打开：<https://gxzx-coze-api.idea.edu.cn/main>
2. 页面上会出现「管理员登录」。
3. 在「用户名」里输入 `admin`。
4. 在「口令」里输入平台同事给你的初始口令。
5. 点「登录」。

说明：

- 用户名当前是 `admin`；如果你已经让平台同事开了自己的账号，就用你自己的用户名。
- 初始口令是平台同事单独给你的，不要发到群里、邮件里或截图里。
- 登录成功后，同一个页面会变成管理台首页（登录框消失）。

### 1.2 第一次登录后：马上改密码

1. 在首页往下找到「账号管理」。
2. 在「修改我的口令」里：
   - 「当前口令」：填你刚登录用的口令。
   - 「新口令」：填一个新口令（至少 8 位，建议字母+数字+符号）。
3. 点「修改」。
4. 看到「口令已更新」就成功了。

改完之后：

- 其他电脑/浏览器会用旧口令登录不上，需要重新登录。
- 平台同事给你的初始口令就没有用了，可以告诉平台同事删掉。

### 1.3 退出登录

- 页面右上角有「退出登录」，点一下就会回到登录页。
- 在公共电脑上用完，一定要点「退出登录」，不要只关浏览器。
- 关闭标签页不等于退出，别人再打开可能还是你的登录状态。

### 1.4 忘记密码 / 账号被锁

**忘记密码**：

- 找另一个管理员，在「账号管理」里点你的账号旁边的「重置口令」。
- 如果只有你一个管理员，联系平台同事处理。

**账号被锁**：

- 连续输错 5 次密码，系统会锁 1 分钟；再错会锁得更久（最长 30 分钟）。
- 页面会提示还要等多少秒，等够时间再试。
- 不要连续猛点「登录」，那样只会锁得更久。
- 如果是别人输错导致你被锁，也等一会儿就好。

## 2. 首页：一眼看懂系统状态

登录后，首页从上到下有三块：

### 2.1 系统状态

这里用一张张卡片显示系统当前情况。你主要看：

| 看到的内容 | 你可以怎么理解 |
|---|---|
| `state` 显示 `ok` | 系统总体正常 |
| 发布版本 / 版本号 | 当前使用的数据版本，平台同事更新数据后会变 |
| 索引状态 | 系统的“查找目录”是否正常；显示 `ok` 就好 |
| 数据新鲜度 / 生成时间 | 数据是什么时候更新的；时间越近越好 |
| 访问日志 | 有多少人用过、有多少轮问答 |
| 磁盘 | 服务器空间够不够；剩余空间越多越好 |
| 配置 | 系统的设置文件是否正常 |

**看到 `unavailable`、`missing` 或英文提示怎么办**：

- 先看系统还能不能正常问答（打开「对话」问一句）。
- 如果能正常用，把这些提示截图发给平台同事确认，不用自己处理。
- 如果问答也不正常，直接联系平台同事，并说明“从什么时候开始、哪个页面、截图”。

### 2.2 快捷入口

首页中间有一排入口，点一下就能去对应页面：

- 管理配置
- 访问日志
- 数据浏览
- 任务运维
- 上传导入（有时会隐藏，见第 7 节）
- Seed 管理（有时会隐藏，见第 8 节）
- 对话

找不到某个入口时，不代表页面没了；可以直接在浏览器地址栏里的网址后面加上对应页面名，或问平台同事。

### 2.3 账号管理

在首页下半部分，分两块：

- 左边「账号列表」：看现在有哪些管理员账号，可以「重置口令」「删除」。
- 右边「修改我的口令」：改自己的密码。

具体操作见第 3 节。

## 3. 账号管理（给同事开账号）

> 这一节的操作会立即生效，做之前确认对象别点错。

### 3.1 新建账号

1. 首页 →「账号管理」→ 左边「新账号」。
2. 输入同事的用户名（例如 `zhangsan`，不要用中文和空格）。
3. 点「创建」。
4. 页面上会出现一行：**新账号的初始口令（仅显示一次）**。
5. 马上把这个用户名和初始口令单独发给同事，让他登录后立刻改密码。

注意：

- 初始口令只显示一次，刷新页面就看不到了。没记下来就只能「重置口令」。
- 新账号也是管理员权限，能看数据、改数据、看日志；只给需要的人开。

### 3.2 重置口令

1. 在「账号列表」找到要重置的账号。
2. 点「重置口令」。
3. 页面会显示一个新的初始口令（只显示一次）。
4. 把这个新口令单独发给本人，让他登录后马上改。

注意：

- 点下去就生效，没有“确认”弹窗；旧口令不能再用，对方会被要求重新登录。
- 不要频繁重置；重置前先和本人说一声。

### 3.3 删除账号

1. 在「账号列表」找到要删除的账号。
2. 点「删除」。
3. 删除后该账号立即不能登录。

注意：

- 点下去就生效，没有“确认”弹窗，也不能撤销。
- **最后一个管理员账号不能删除**；如果提示 `last_account`，说明系统不允许把管理员删光。
- 删除前确认不是在职同事，或先建好替代账号。

### 3.4 账号规则（简单版）

- 用户名：1–64 个字符，不能有空格。
- 密码：至少 8 位，最长 256 位。
- 一个人一个账号，不要共用。
- 离职/换岗及时删除或重置。
- 密码不要写在便签、群聊、邮件里。

## 4. 数据浏览（最常用）

打开「数据浏览」，这里是系统的四类数据：

- **企业**
- **论文**
- **专利**
- **教授**
- 还有一个 **Gaps / 知识缺口** 页签，是用户反馈“答得不好/证据不足”的记录，只读。

### 4.1 选择领域和搜索

1. 在页面上方点「企业 / 论文 / 专利 / 教授」切换领域。
2. 在搜索框输入关键词（名称、标题、简介里的字都可以）。
3. 点「搜索」。
4. 想恢复全部数据，点「清除」。

列表默认每页 25 条，底部有「上一页 / 下一页」。

### 4.2 看一条数据的详情

点列表里的任意一条，右侧会出现「证据与限制」，包括：

- **关键字段**：这条数据的主要信息（行业、地区、年份、引用数等）。
- **证据标识**：这条数据来自哪里、绑定了哪些证据。
- **字段血缘**：这个字段是怎么来的（记录条数）。
- **限制**：这条数据的使用限制。
- **修正记录**：以前有没有人改过、改了什么、为什么改。
- **查看关联**：看它和别的数据的关系（例如企业关联的专利、教授关联的论文）。

### 4.3 修改一条数据（字段纠错）

只有部分字段可以改，页面上会显示「改」按钮。

1. 打开一条数据的详情。
2. 在「关键字段」里找到要改的字段，点旁边的「改」。
3. 在文本框里填新内容。
4. 在「修改原因（必填）」里写清楚为什么改（例如“官网信息已更新”）。
5. 点「保存」。
6. 保存后字段旁会出现「已修正」；下面「修正记录」里能看到这次修改。

可以改的字段：

| 领域 | 可以改的内容 |
|---|---|
| 企业 | 名称、所属行业、地域、成立日期、简介 |
| 论文 | 标题、发表场所、年份、引用数、公开日期 |
| 专利 | 标题、专利类型、公开日期、申请日期 |
| 教授 | 姓名、机构、院系、H 指数、引用数 |

注意：

- 修改原因一定要写，系统会记录是谁、什么时候、为什么改。
- 改错了可以在「修正记录」里点「撤销」恢复。
- 浏览页会立即显示新值；对话页的回答要等平台同事下次更新数据后才会用上新值。

### 4.4 新增一条记录

1. 在数据浏览左栏点「新增记录」。
2. 填写：
   - **名称 / 标题**（必填）：企业/教授填名称，论文/专利填标题。
   - **补充字段**（可选）：可以留空。如果要填，按 `{"字段名": "值"}` 的格式；不确定就留空或问平台同事。
   - **录入原因**（必填）：为什么新增这条。
3. 点「提交」。

注意：

- 新增的记录会立即进入对话页的检索，用户提问时可能用到。
- 页面没有删除按钮；如果录错了，联系平台同事处理。
- 不要把长文档硬塞进「补充字段」；企业文档请用下面的「上传文档」。

### 4.5 上传企业文档

这个功能只在**企业**领域显示。

**支持的文件**：PDF、Word（.docx）、TXT、Markdown（.md）、Excel（.xlsx）。

Excel 的处理方式：系统会先识别表结构——扫描表头，判断这是企业、教授、专利还是论文表，并把列映射到对应字段。预览会显示识别出的领域、置信度和字段映射；确认时可以选“按识别结构入库”，把行写进对应的数据表，也可以只用文本入库作为资料召回。

单次最多读取约 24,000 字符；大表建议按企业/主题拆分。

**步骤**：

1. 企业领域 → 左栏「上传文档」。
2. 选择文件 → 点「解析文档」。
3. 系统会把文件内容读出来，显示：
   - 读出了多少字
   - 会生成多少个“召回块”（用于对话检索的片段）
   - 是否因为太长被截断
4. 检查预览文字，可以直接在文本框里修改。
5. 填写：
   - **企业名称**（必填）
   - **文档标题**（可选）
   - **关联已有企业 ID**（可选；不确定就留空）
   - **入库原因**（必填）
6. 点「确认入库」。
7. 成功后提示「已入库 · N 个召回块即时生效」，文档列表里出现这条记录。

**撤销**：在文档列表里点「撤销」，这条文档就不再参与检索。

注意：

- 当前环境单个文件建议不超过 **1MB**；超过会提示 `413 Request Entity Too Large`。大文件请压缩/拆分，或联系平台同事。
- 文档会写入人工召回库，管理员可在文档列表看到；对话召回是否命中取决于问题与检索车道。上传前确认内容准确、不涉密。
- 上传记录里会显示操作人和时间，便于追溯。

### 4.6 知识缺口（Gaps）

- 点「Gaps / 知识缺口」页签。
- 这里显示用户在对话页点「反馈」时留下的记录：
  - 回答不对
  - 证据不足
- 这是只读的；用来发现“用户觉得哪里答得不好”，可以定期看，反馈给平台同事。

### 4.7 数据浏览注意事项

- 改动会记录操作人（你的登录账号），请按实际情况填写原因。
- 只改自己确认过的信息；不确定就截图问平台同事。
- 不要改与业务无关的字段；不要批量乱改。
- 页面显示的数据量、证据数量会随发布版本变化，以页面为准。

## 5. 访问日志（看用户问了什么）

打开「访问日志」，可以看到用户实际问了什么、系统怎么回答、有没有报错。

### 5.1 筛选

页面上方可以组合筛选：

- **搜索框**：按提问内容搜。
- **状态**：全部 / 已完成 / 错误 / 中断。
- **提问类型**：系统自动识别的类型。
- **提问身份**：例如匿名用户。
- **开始 / 结束**：按日期范围。
- 点「查询」应用筛选，点「重置」清空。

### 5.2 看会话和回答

页面分三块：

- **概览**：会话数、轮次、错误率、错误轮次、中断轮次、保留期。
- **会话列表**（左边）：一次连续对话算一个会话；点一个会话。
- **轮次详情**（右边）：每次提问和回答，包括：
  - 用户问题
  - 系统回答（可展开）
  - 引用来源
  - 建议追问
  - 耗时、回答风格、提问类型、状态

**排查思路**：

1. 如果错误率高：状态选「错误」，按时间找第一条错误，点开会话看详情。
2. 如果某类问题答不好：按类型筛选，找几个例子。
3. 如果用户反馈“答得不对”：到「数据浏览 → 知识缺口」对照看。

### 5.3 导出

- 点「导出 CSV」或「导出 JSONL」，会导出当前筛选范围内的数据。
- 导出文件里有用户提问和回答，可能含业务信息；按公司规定保存，不要随意转发。

### 5.4 注意事项

- 「提问身份」为匿名，是正常的：对话页对公众开放，不要求登录。
- 页面上的时间按国际标准时间（UTC）显示；北京时间要加 8 小时。
- 保留期是系统设置，过期数据可能被清理；需要长期留存请提前导出。

## 6. 任务运维（看任务计划、跑日常采集）

打开「任务运维」，可以看到系统预定义的采集/导入任务和它们的计划时间。

> **本机已启用「日常采集」的 7 个任务。**
>
> - **日常采集**：企业新闻、企业官网产品、论文检索/摘要/DOI、教授主页等任务都可以在这台服务器上运行；每次有条数上限，通常几分钟到几十分钟。
> - **教授采集源**：可以打开「Seed 管理」页，查看/新增/修改学校名册，点「检查名册」或「开始抓取」。
> - **高级操作 / 数据导入**：仍由平台侧执行，本机不要点。
> - 采集任务会消耗网络检索或大模型额度；只在允许的时间段、且采集开关打开时运行。

### 6.1 看任务

页面分几组：

- **日常采集**：企业新闻、企业官网产品、论文信息、教授主页等（本机可运行）。
- **数据导入**：把上传的表格真正写进系统（平台侧运行）。
- **教授采集源**：按学校维护名册并触发抓取（本机可操作）。
- **高级操作**：更新检索索引、检索自检等，一般不需要手动跑。

每个任务会显示：

- 运行安排（计划时间）
- 最近运行（本机跑过的记录）
- 状态
- 按钮：立即运行、复位熔断、查看

### 6.2 企业新闻采集怎么用

1. 找到「企业新闻采集」卡片。
2. 看「运行安排」：应显示「每周一 02:00」，「下次」是下周一 02:00（北京时间）。
3. 想马上补一次：点「立即运行」，确认后等待。一次最多处理 200 家企业，通常需要几分钟到几十分钟。
4. 运行过程中不要重复点；重复点会被系统拒绝（提示已有任务在跑）。
5. 点「查看」看运行详情：成功会显示抓取、写入的条数；失败会显示错误原因，把详情截图发给平台同事。
6. 如果显示「熔断」（连续失败 2 次会自动暂停）：不要反复点。先联系平台同事确认原因；原因排除后，可以点「复位熔断」，再点一次「立即运行」。

### 6.3 运行历史

- 每周一自动运行后，这里会出现一条由「周期」触发的记录。
- 手动点「立即运行」会出现一条由「手动」触发的记录。
- 历史为空或只有旧记录，说明还没到下一次运行时间；可以点「立即运行」验证。
- 如果出现「跳过 · 窗口外」：说明触发时间不在系统允许的凌晨时段；每周一 02:00 的自动运行在时段内，不会跳过。手动「立即运行」不受这个时段限制。
- 失败的记录不要连续重点，避免触发熔断。

### 6.4 其它采集任务

- 「企业官网产品重抓」「论文标题检索回填」「论文摘要中文回填」「论文 DOI 校验」「教授主页重爬」「教授主页论文增量」也在这台服务器上运行，每次有条数上限（20–100 条），可能耗时几分钟。
- 运行中不要重复点；重复点会被系统拒绝（提示已有任务在跑）。
- 「高级操作」（更新检索索引、预演、检索自检）、「数据导入」仍由平台侧执行，本机不要点。
- 看到灰色、不可用的任务，不要强点。
- 需要更新这些数据：按页面提示操作；不确定就先问平台同事。

### 6.5 教授采集源（Seed）

1. 点「教授采集源」→「去 Seed 管理页」。
2. 页面按学校列出现有名册；可以新增、修改、删除学校名册 URL。
3. 「检查名册」只验证能不能解析，不写入数据；「开始抓取」按选择的抓取范围真实抓取并写入。
4. 抓取会访问学校网站、消耗检索额度；运行中不要重复点。
5. 失败时点「查看」看原因，把详情截图发给平台同事。

## 7. 上传导入（XLSX 表格）

这个页面用于把 Excel 表格（.xlsx）导入系统。

> **当前客户现场上传导入不可用**：页面会提示「构建期 PostgreSQL 不可用 / 提交入口已隐藏」，只能干跑检查表格。实际导入由平台侧执行；需要导入表格时联系平台同事，不要把表格直接当成已导入。

### 7.1 什么时候用

- 有新的企业/专利/教授表格需要批量导入。
- 平台同事让你上传某个表格。

### 7.2 操作步骤

1. 打开「上传导入」。
2. 选择「知识域」：企业 / 专利 / 教授（**不支持论文表格**）。
3. 选择 `.xlsx` 文件。
4. **先干跑**：勾选「干跑（只解析不写入）」，点「上传」或「干跑」。
   - 干跑只检查表格能不能读、字段对不对，不写数据、不占用导入额度。
5. 干跑没问题后，取消勾选，点「上传」。
6. 上传成功后会生成一个“上传编号”；如果平台同事已开启导入，系统会自动排队。
7. 导入结果由平台同事通知；当前现场不在本机跑导入任务，不要到「任务运维」里手动点。

### 7.3 上传记录

- 页面下方「上传记录」显示：上传编号、领域、文件名、内容哈希（文件指纹，用来判断是否重复）、状态、闸门运行（对应的导入任务）、时间。
- 点一条记录，可以在「上传详情」看解析摘要和失败原因。
- 同一个文件（同内容、同领域）重复上传会被拒绝，并告诉你第一次的上传编号；这是正常的去重。

### 7.4 当前限制（重要）

- 如果页面上看不到「上传」按钮，或提示「本机没有构建期 PostgreSQL / 提交导入不可用」，说明平台侧还没开启这个功能。**这不是你的操作问题**，联系平台同事即可。
- 干跑通常仍然可用，可以用来检查表格。
- 单个文件大小受平台限制；如果提示 `413` 或 `Request Entity Too Large`，说明文件太大，压缩/拆分后再试，或联系平台同事。
- 不要修改表格的列名/格式后反复试；先问平台同事要模板。

## 8. Seed 管理（教授采集源）

这个页面用于维护“教授数据从哪里抓”：学校、院系、名册网址。

### 8.1 什么时候用

- 要新增一所学校/院系的教授名册。
- 某个学校的名册网址变了，需要更新。
- 平台同事让你检查某个名册能不能抓。

### 8.2 新增采集源

1. 打开「Seed 管理」→「新增采集源」。
2. 填写：
   - **学校**（必填，例如“南方科技大学”）
   - **院系**（可空，例如“计算机科学与工程系”）
   - **名册 URL**（必填，学校官网的教师名录页面）
3. 点「新增采集源」。

注意：

- 名册 URL 必须是学校/院系的公开教师名录页面，不要填内网地址、登录后的页面或带密码的链接。
- 同一网址不能重复添加。
- 如果提示“缺少适配器”，说明这所学校还没有对应的抓取规则；把学校名和网址发给平台同事。

### 8.3 检查名册和抓取

1. 在「采集源清单」找到学校。
2. 先点「检查名册」：只检查能不能读，不写入数据。
3. 检查通过后，选择「抓取范围」：
   - 前 20 条
   - 前 50 条
   - 前 100 条
   - 全部
4. 点「开始抓取」。
5. 到「运行记录」看结果。

### 8.4 运行记录

- 显示每次运行的模式（检查名册 / 抓取前 N 条 / 全部抓取）、状态、触发方式、操作人、开始时间。
- 失败时看原因；修好后再重试。

### 8.5 当前状态

- 客户现场已启用 Seed 管理；页面能正常列出现有名册。
- 如果仍提示「控制台没有配置数据库」或「seed 管理不可用」，联系平台同事检查服务配置，不是你的操作问题。
- 「检查名册」和「开始抓取」都会真实访问学校网站；抓取会消耗检索额度，运行中不要重复点。

## 9. 管理配置中心（高级设置）

> **这一页是高级设置。日常不需要动。除非平台同事明确指导，不要修改任何字段、密钥或模型。**
> 改错可能导致问答不可用；保存后通常还需要平台同事重启服务才生效。

打开「管理配置」，你会看到四张卡片：

| 卡片 | 大致作用 | 你需要做什么 |
|---|---|---|
| 采集与构建 | 控制四个领域是否采集、每轮最多用多少资源、什么时间段跑 | 一般不用动；平台同事让你关某个领域时再改 |
| 检索与回答 | 控制检索/回答的运行参数 | 一般不用动；调整会影响回答质量和速度 |
| 存储与保留 | 看数据文件、日志保留天数、磁盘空间 | 主要用来“看”；改路径/保留天数前问平台同事 |
| 模型与连接 | 看对话模型、采集模型、嵌入模型、重排、Web 搜索的连通性 | 主要用来“看”和“测试”；换模型/密钥必须由平台同事操作 |

### 9.1 你可以安全做的

- 看每张卡片显示的状态。
- 在「模型与连接」里看某个连接是否“已启用/已配置”。
- 在平台同事指导下，点「测试连通性」检查是否正常。
- 点开最下面的「只读快照」，看当前设置（只读，不会改东西）。

### 9.2 不要做的

- 不要改「采集开关」「资源额度」「时间窗口」，除非平台同事明确要求。
- 不要改「模型名」「服务地址（Base URL）」「密钥」；改错会导致问答失败。
- 不要点「清除密钥」；那会让对应服务不可用。
- 不要改「存储与保留」里的路径类设置（例如存储目录、索引路径）；这些是平台同事的发布操作。
- 看到「保存本卡」按钮，不确定就不要点。

### 9.3 如果平台同事让你改

1. 只改他指定的那一个字段。
2. 改完点「保存本卡」。
3. 把页面提示截图发给他。
4. **不要自己重启服务器**；重启由平台同事执行。
5. 保存后页面可能提示“需重启生效”，这是正常的；等平台同事重启后再验证。

### 9.4 保存 ≠ 立即生效

- 「保存本卡」只是把设置存下来，正在运行的系统不会马上变。
- 大多数设置要平台同事重启服务后才生效。
- 「测试连通性」只是当场试一下，不会保存设置。
- 所以顺序是：改 → 保存 → 告诉平台同事 → 重启后验证。

## 11. 遇到问题怎么办

### 11.1 常见提示对照表

| 你看到的提示 | 大概意思 | 你可以怎么做 |
|---|---|---|
| `invalid_credentials` / 「用户名或口令错误」 | 用户名或密码不对 | 确认用户名是 `admin`，确认密码；注意大小写 |
| `locked` / 429 / 「请 N 秒后重试」 | 密码错太多次，被临时锁定 | 等提示的秒数；不要连续试 |
| 页面突然跳回登录页 / `authentication_required` | 登录过期了 | 重新登录 |
| `current_password_incorrect` | 改密码时“当前密码”填错 | 重新填当前密码 |
| `last_account` | 不能删除最后一个管理员 | 先建一个新的管理员，再删 |
| `account_exists` | 用户名已存在 | 换一个用户名 |
| `duplicate_upload` | 这个文件已经上传过 | 用提示里的第一次上传编号；不要重复传 |
| `413 Request Entity Too Large` | 文件太大 | 压缩/拆分；或联系平台同事 |
| `upload_requires_postgres` / 「提交导入不可用」 | 平台侧未开启上传导入 | 联系平台同事；干跑仍可用 |
| `console_database_not_configured` / 「seed 管理不可用」 | 平台侧未开启 Seed 管理 | 联系平台同事 |
| `job_breaker_open` / 「任务已熔断」 | 任务连续失败，自动暂停 | 把运行详情发给平台同事；不要自己复位 |
| `job_already_running` | 任务正在跑 | 等它跑完 |
| `cross_site_request_refused` | 页面安全校验失败（通常是网络/代理切换） | 刷新页面、重新登录；还不行就截图给平台同事 |
| 页面显示 `unavailable` / `missing` | 某个技术组件状态异常 | 如果问答正常就先忽略；异常时截图给平台同事 |

### 11.2 联系平台同事时，请提供

1. **截图**：整个页面，包括报错文字。
2. **时间**：大概几点、什么操作之后出现。
3. **页面**：你在哪个页面（首页/数据浏览/访问日志/任务运维/上传导入/Seed 管理/管理配置）。
4. **你做了什么**：点了哪个按钮、填了什么内容（不要发密码）。
5. **影响范围**：只有你这里出现，还是其他人也不行；对话页还能不能用。

### 11.3 不要做的事

- 不要把密码、初始口令、密钥发到群里/邮件里。
- 不要删除最后一个管理员账号。
- 不要在没有和本人确认的情况下重置/删除别人的账号。
- 不要在平台同事不知情时改「管理配置」里的模型、密钥、路径。
- 不要连续点「登录」「立即运行」「复位熔断」；企业新闻采集运行中不要重复点。
- 不要把客户敏感文档上传到错误领域；企业文档只走企业领域的「上传文档」。
- 不要尝试自己重启服务器或修改系统设置；这些由平台同事负责。

## 12. 名词解释

| 名词 | 简单解释 |
|---|---|
| 管理台 | 你现在登录的这个后台，用来管账号、看数据、看日志 |
| 对话页 | 用户提问的页面（`/chat`），对公众开放，不需要登录 |
| 会话 | 一次连续的对话（可以包含多轮提问） |
| 轮次 | 一次提问 + 一次回答 |
| 发布版本 | 当前系统使用的一版数据；平台同事更新数据后会变 |
| 索引 | 系统的“查找目录”；数据更新后要更新索引，用户才能搜到新内容 |
| 召回块 | 文档被切成的小段，用于对话检索 |
| 证据 | 这条数据/回答是从哪里来的 |
| 字段血缘 | 这个字段的来源和加工记录 |
| 知识缺口（Gaps） | 用户反馈“答得不对/证据不足”的记录 |

| 干跑 | 只检查、不真正写入（上传表格前先用它） |
| Seed | 教授数据的采集源：学校/院系 + 名册网址 |
| 熔断 | 任务连续失败后自动暂停，防止一直失败 |
| 管理员 | 能登录管理台的人；当前所有账号都是管理员 |
| 首启口令 | 系统第一次启用时生成的管理员初始密码 |

## 14. 安全提醒

- 一个人一个账号，不共用密码。
- 首次登录后马上改密码；不要一直用初始口令。
- 密码至少 8 位，建议字母+数字+符号；不要用生日、手机号、`12345678`。
- 在公共电脑上用完点「退出登录」。
- 不要把密码、初始口令、密钥写在便签、群聊、邮件或截图里。
- 不要删除最后一个管理员；离职/换岗及时处理账号。
- 上传文档前确认内容准确、不涉密；只上传到对应领域。
- 「删除」「重置口令」点下去就生效；「立即运行」只对「企业新闻采集」使用；「保存本卡」需要平台同事重启后才生效。点之前看清楚。
- 不确定的操作，先问平台同事；不要自己试。
