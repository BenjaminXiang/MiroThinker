# 深圳科创数据平台客户介绍 PPT 设计说明

## 目标

制作一份 2 页、面向客户现场讲解的 PPT，回答两个问题：

1. 客户能用这套系统解决什么问题，答案为什么可信。
2. 这套系统为什么具备可运营、可扩展、可持续迭代的工程能力。

听众假设为业务负责人和技术负责人混合团队，因此页面文案先讲价值，再用架构和界面证据支撑，不把底层模型 benchmark 直接当作平台交付指标。

## 备选叙事方式

### 方案 A：业务场景优先

第一页用一个跨域问题引出教授、企业、论文、专利四类数据；第二页展示后台运营闭环。

- 优点：业务负责人容易代入，现场故事顺。
- 风险：若架构图过轻，技术负责人看不到系统边界和质量控制。

### 方案 B：架构分层优先

第一页直接给出数据层、服务层、交互层架构；第二页再用截图展示使用效果。

- 优点：技术信息完整，系统能力表达清楚。
- 风险：业务负责人第一眼不容易理解价值，容易像技术方案宣讲。

### 方案 C：价值入口 + 工程底座（采用）

第一页回答“从问题到答案发生了什么”，第二页回答“系统如何长期稳定地完成这件事”。每页只保留一条主线，截图作为运行证据嵌入对应位置。

- 兼顾两类听众，适合 3–5 分钟客户介绍。
- 叙事与仓库真实能力一致：四域检索、Canonical-v2 serving、统一证据字段、质量门、运营后台和回放验证。

## 页面设计

### 第 1 页：从一句话问题到可追溯答案

标题：深圳科创数据平台：面向科创生态的对话式检索入口

左侧放客户价值摘要：用户用自然语言提问，系统覆盖教授、企业、论文、专利四个数据域，并支持单域检索、跨域聚合和多轮追问。

中部放横向流程：

`问题理解 → 意图路由 → 单域/跨域检索 → 多源召回与 rerank → 结构化答案 + 来源证据`

右侧放运行界面截图。首选本地真实素材：

- `baseline-home.png`：数据总览、数据质量动态、运营指标。
- `baseline-professors-list.png`：教授域筛选、列表和已验证论文字段。
- 若能启动本地服务，再补 `/chat` 流式对话截图；无法启动时不使用伪造对话内容。

页面记忆点：**把分散的科创数据，变成可检索、可解释、可继续追问的答案。**

### 第 2 页：可运营、可迭代的系统架构

标题：四域数据底座 + Canonical-v2 服务层，支撑持续演进

用三层架构图表达边界：

- 交互与运营层：用户对话、数据总览、导入任务、质量问题、人工审核。
- 统一服务层：Canonical identity、领域投影、关系投影、证据落地、流式会话、多轮上下文。
- 数据与检索层：PostgreSQL 事实库、Milvus 向量库、Web Search 补充通道；教授/企业/论文/专利四域独立维护并遵循统一合同。

右侧列出工程证据：统一稳定 ID 与 `evidence`、质量门、跨域关系、回放/重放验证、可替换模型与检索组件。配图仍使用后台总览和教授列表截图的裁剪版，分别标注“可运营”和“可追溯”。

## 视觉语言

- 16:9 宽屏，白底为主，深海军蓝作为结构色，青绿色作为系统运行和证据强调色，少量琥珀色表示质量/告警。
- 采用清晰的网格和细线连接，不使用大面积渐变、装饰性圆球或堆叠卡片。
- 标题使用短句，正文控制在能现场扫读的长度；架构术语保留英文原名并给出中文解释。
- 图片只使用仓库真实截图或实际运行截图，所有数据口径与现有文档一致，不写未经验证的 ready 数量或准确率。

验收标准：

1. 两页均可脱离口头补充理解主旨，页面之间形成“价值 → 架构证据”的递进。
2. 至少包含两张真实系统截图；截图不遮挡关键文字，分辨率适合投屏。
3. 架构图能对齐项目实际模块：四域、PostgreSQL/Milvus、Canonical-v2、证据与质量控制、运营后台。
4. PPTX 可正常打开；如生成 PDF，PDF 页数为 2 且无字体替换导致的溢出。
