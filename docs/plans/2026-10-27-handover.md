## 5. 重建为什么暂缓

- 源是**清单驱动**的：staging 的 `*.source` 由构建按 `sha256(member_id)` 复制，改内容要改
  成员哈希 → 清单 `content_sha256` → 发射参数，属于构建侧数据手术；
- 收益重估后偏小：论文 claim 本来就渲染作者；清模板是"去噪"不是"变强"。

**重启条件**：攒够一批数据变化（补全 + 链接扩充）再一次性付 20 小时；
届时 `materialize_pack_links.py` 与 `professor-cleaned.source` 直接复用。

## 6. 下一步 runbook：20 位补全试点

```bash
# 1) 选人：薄画像（<200 字）且属于常用机构；导出 20 位 id
psql "$COLLECTION_DSN" -c "select professor_id, canonical_name from professor
  where length(coalesce(profile_summary,''))<200 limit 20"

# 2) 补全（本地或客户机；DeepSeek 搜索 → 抓页 → 身份校验 → 合成）
cd apps/miroflow-agent
DEEPSEEK_API_KEY=… uv run python scripts/run_professor_web_enrich.py \
  --dsn "$COLLECTION_DSN" --professor-id <id> --limit 1 \
  --min-summary-len 500 --llm-profile deepseekv4flash

# 3) 写 manual recall（立即进服务，不需要重建）——走管理台 manual-recall 接口，
#    每条带来源 URL；或复用 10-26 的人工记录脚本。

# 4) 验收：20 条可见；每条 ≥120 字且 ≥10 条事实；抽 3 位提问能答出并带 citation；
#    `just eval-gate` 不劣于 77/120。

# 5) 回滚：manual recall 支持 tombstone，按记录撤销。
```

**成本**：每位约 5–9 个页面抓取 + 1 次合成；20 位约 15–30 分钟。
**已知坑**：`PROFILE_SUMMARY_MIN_CHARS` 已降到 120（200 会拒掉真实摘要）；
`--min-summary-len 500` 是为了强制重跑已有画像。
