## 1. 为什么重新排一次序

功能不缺，缺的是**判断什么算完成**。现有三条线（客户现场补齐、标准问答对齐、教授画像闭环）各自都在推进，但共用一套失真的地基：

- 客户机 `100.64.0.96:/root/deploy/fullstack-v2/code` **不是 git 仓库**，10-21 至 10-26 有 31 个 py 文件被改，`run.sh` 被重写；
- 这 31 个文件相对 `switch/embedding-model-to-qwen37-flash`：9 个一致、18 个不同、4 个在该分支根本不存在（只在 10-23 的 `codex/canonical-v2-s12a-ready` 快照里）；
- 本地 `:18188` 与客户机走**同一条启动链**（`serve_s12e_port.py → complete_candidate_runner → import backend.main`），但进程自 10-16 未重启，Python 在启动时就冻结了当时的 import、环境也停在当时（无答案缓存开关）——它验证不了 10-16 之后的行为。这是「进程冻结」，不是「另一个应用」（第 1 轮判断已在第 2 轮更正）；
- `release/customer-test` 停在 8-19，与 AGENTS.md 写的「客户热更新线」已经脱节。

结论：最新行为只活在一台机器的文件系统里，任何重封/换机/重建都会静默回退，且没有测试能发现。

## 2. 四道闸门

```text
闸门 1 可复现  ──→  闸门 2 可度量  ──→  闸门 3 数据竖切  ──→  闸门 4 运行化
（代码归位）        （一条命令出分）      （教授×论文闭环）      （调度+观测+切包）
```

| 闸门 | 目标 | 退出条件 |
|---|---|---|
| 1 可复现 | 部署树 = git 树，漂移可被机器发现 | 回灌分支 + drift 检查 0 差异 + 4 条采纳行为有测试 |
| 2 可度量 | 一条命令给出分数与逐题 diff | `just eval-gate`：27 轮 + 基线对比 + 双分制（exact / product） |
| 3 数据竖切 | 20 位教授端到端打穿 论文→画像→检索 | `paper.professor_ids` ≥60%、模板率 <10%、q27 稳定 |
| 4 运行化 | 采集→画像→pack 的周期刷新 + 观测 | 指标看板 + 定时任务 + 一次计划内切包 |
