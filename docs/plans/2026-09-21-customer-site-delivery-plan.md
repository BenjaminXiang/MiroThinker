## 4. 路径契约（为什么必须"同构"）

迁移的核心约束不是"别改路径"，而是**三处冻结**：

1. 服务包 `manifest.json` 里记着 `index_root` 的绝对路径；
2. 索引根的 marker 里也记着 `root`；
3. serving bundle 里**逐字符**比对第 1、2 项与 CLI 传入值。

⇒ 目标机上这三者必须逐字符一致；否则只能重新封印（41 分钟 + 需搬 7.8 GB 构建信封），代价远超收益。

**必须同构的路径（服务期真正会被 stat/读取的）**：

| 路径 | 用途 | 现场形态 |
|---|---|---|
| `/var/tmp/mirothinker-data-v2/serving-pack-run16-readerbound/` | 服务包 | 实体文件 |
| `/var/tmp/mirothinker-data-v2/index-v3-v2/` | 索引根 | 实体文件 |
| `/var/tmp/mirothinker-canonical-v2-s12f/` | 状态目录（账号库/会话密钥/首启口令/访问日志/更正） | **目录必须先存在**；不存在时只有一行 warning，管理面直接不可用 |
| `/var/tmp/mirothinker-data-v2/manual-recall-v1` | 手工召回道 | 空目录即可 |
| `<data-rebuild 树>/…/s12a/` | 门禁根目录（`s12a/` 必须存在） | **空目录即可**（信封文件服务期从不打开） |
| 命令文件里其余路径 | 解析期要求存在 | 随 85→11 清理大幅减少（P0-3）；未清理则用空目录/空文件占位 |

> 打包时生成 `site-paths.txt`（逐条列出 + 就地检查命令），现场按它创建与核对；
> 上面表格以 F1/F2 回归后的实测为准。

### P1 · 现场环境（0.5 天，甲方或我方远程）

同名用户 → 同构路径 → `uv sync`（联网重建 venv；`.venv` 里的 editable 指针是绝对路径，不能直接搬）→ Chromium（`uv run playwright install chromium` + `install-deps`，需 root）→ `sudo loginctl enable-linger <user>` → 预建状态目录与门禁目录 → 跑 `preflight.sh`。
**验证点**：`preflight.sh` 全绿；`uv run python -c "import src"` 可用。

### P2 · 落位与校验（0.5 天）

传三批货 → 逐文件 `sha256sum -c checksums.sha256` → 属主/权限统一 → 核对 §4 路径逐字符一致。
**验证点**：校验和全对；路径比对脚本输出"一致"。

### P3 · 配置（0.5 天，含首启）

1. 起服务（`systemd --user start canonical-v2-backend`；**首启约 291 s**，日志按相位 author… 完成）；
2. 登录 `/main`（首启口令在状态目录的 `admin-initial-password.txt`，**立即改密**）；
3. `/admin` 配置：chat LLM 选档 + 密钥 → **嵌入端点 + 连测（身份探针）** → rerank（按需）→ Bocha/Serper 密钥；
4. 装 PG 时：建库 + `alembic upgrade head`（V042/42 表）+ systemd drop-in 注入 `DATABASE_URL`（**受管配置不允许承载 DSN**）。
**验证点**：`/chat` `/main` 200；`/admin` 各卡状态正常且连测通过。

### P4 · 首启冒烟与验收（0.5 天）

见 §6。**验证点**：验收清单逐条勾选并留证（截图/命令输出）。

## 6. 验收标准（分层，逐条留证）

| 层 | 判定 | 命令/方式 |
|---|---|---|
| 启动 | systemd active；日志无 release/integrity 错误；boot ≤ 5 min | `systemctl --user status`；日志相位 |
| 检索回归 | **replay 门 7/7**（G1–G7） | `cd apps/admin-console && uv run python scripts/replay_fix_round1.py --base-url http://127.0.0.1:18188 --out-dir /tmp/accept` |
| 功能抽样 | 点名 / 语义 / 关系 各一问，本地引用齐全 | `/chat` 人工 + 引用卡 |
| 性能 | TTFT：三例均 **≤30 s**（目标 ≤20 s） | 浏览器/日志时间戳 |
| 管理面 | `/main` 登录、改密、审计、`/admin` 保存+连测、`/browse`、`/logs` 可用 | 逐页 200/302 + 操作一次 |
| 降级 | 嵌入端点不可达时**仍出答案**、TTFT 不超预算、trace 记 unavailable | 临时改地址为黑洞（验收后改回） |
| 采集线（若装 PG） | `/seeds` 可开、预览抓取能跑、任务历史可见 | 页面操作 + 日志 |
| 回退 | 换包 + 重启一次成功回到旧包 | 演练并记录耗时（291 s） |
| 数据 | 包自报计数与文档一致（company/paper/patent/professor） | `/admin` 状态面板 |

## 7. 回退方案（三级）

1. **换包回退**：命令文件里 `--serving-pack` 指回旧包 + 重启（291 s；旧包与旧命令文件原样保留）；
2. **配置回退**：`/admin` 改回上一版配置（点"待重启"后重启生效）；
3. **整体停服**：`systemctl --user stop canonical-v2-backend`，对外由反代摘除。

首启若硬失败，日志会点名是 pack / index root / bundle / 门禁目录哪一项——不需要猜。

## 8. 周期更新与"后续推送"

**模型（本次交付定版）**：构建在**我方**执行，甲方只做落位与切包。

| 环节 | 在哪跑 | 耗时 | 谁 |
|---|---|---|---|
| 采集 + 重建 | 我方 | ~8 h | 我方 |
| 封印 | 我方 | ~41 min | 我方 |
| 推包（增量传输） | 网络 | 视带宽 | 我方/甲方 |
| 落位校验 + 切包 + 重启 | 甲方机器 | **~291 s 停机** + 校验 | 甲方（按 runbook）或我方远程 |
| 验收探针 | 甲方机器 | ~10 min | 同上 |

**代码补丁推送**：补丁 tar（或 `git bundle`）→ 落位 → `uv sync`（如需）→ 重启（291 s）→ 跑 replay 门。

**为什么甲方不跑构建**：构建需要采集库、源系统凭据、7.8 GB 构建信封与整条校验链，且占机 8 小时；把它放现场会把交付面从"运行一个服务"扩大到"运行一条数据流水线"。等 §10 决策 ② 定了 PG，再评估是否把"单域增量"搬到现场。

## 9. 风险与处置

| 风险 | 触发条件 | 处置 |
|---|---|---|
| 内存不足 | 机器 <64 GB | 提规格；或按最小并发配置（需实测，不承诺） |
| 路径不一致 | 现场未按 §4 同构 | 启动即 fail-closed 并点名；按 `site-paths.txt` 补齐（空目录即可） |
| 嵌入端点不可用/不匹配 | 网络或模型不对 | F1 降级（服务不挂）+ F2 身份探针（页面拦截） |
| 出网受限 | 甲方防火墙 | 白名单（LLM 域名、Bocha/Serper、嵌入端点）；代理无效需透明代理 |
| venv 重建失败 | 现场无外网 | 打包时附离线 wheel 缓存；或提前在我方机器演练 |
| 网页抓取降级 | 缺 Chromium | `preflight.sh` 检查；缺失时告知（抓取质量下降但不崩） |
| 切包停机超预期 | 磁盘慢 | 验收演练一次，实测耗时计入 runbook |
| 密钥泄露 | 明文入库/入 git | 只走加密渠道 + 0600 + `preflight.sh` 校验；日志不含明文 |
