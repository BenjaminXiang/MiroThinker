## 二、里程碑详解

### M1 · 9/9：配置中心上线 + 发布链前置修复

**交付内容**

1. **Milvus Lite close 死锁修复**：数据构建收尾阶段的已知阻塞，是后续所有数据发布功能的技术前置；完成当天以一次完整数据构建验证。
2. **配置中心**（管理区新页面，需登录）：
   - 系统状态面板：当前服务包版本/发布时间/绑定版本号、存储健康、纠错与手工召回计数、磁盘余量；
   - 数据新鲜度面板：四个数据域各自上次成功采集时间与距今间隔，与当前服务包构建时间并排展示；
   - 采集配置：各域采集开关、每轮调用配额上限、执行时间窗口；
   - 外部服务 key 健康检查：搜索/学术 API/本地大模型/重排模型一键探测连通性，页面仅显示 key 尾号，不显示明文。

**排期依据**：风险前置——发布链上最大的阻塞最先排除；配置中心是后续所有管理页面的公共壳。

**验收标准**：页面信息与系统实际状态一致；原状态接口 500 缺陷消失；配置修改落库、服务重启后保留、有审计记录；一次完整构建收尾不挂起。

### M2 · 9/11：任务运行面 + 用户会话审计增强

**交付内容**

1. **任务运行面**：全部采集任务的清单与下次自动运行时间、历史记录（成功/失败/耗时/处理条数）、失败红点告警；**按任务"立即采集"按钮**——与定时任务执行同一套闸门（防重复锁、配额上限、熔断状态），手动触发不绕过任何限制；任务运维动作（Milvus 向量回填、检索效果验证）。
2. **用户会话审计增强**（扩展现有访问日志页）：
   - 身份维度：记录提问者身份（登录用户记账号、公开访问记匿名；不记录 IP）；
   - 组合筛选：时间范围 × 问题类型（A–G）× 身份 × 状态；
   - 导出：按当前筛选条件导出 CSV/JSONL；
   - 概览统计：每日会话数与轮次数、问题类型分布、错误率、热门提问排行。

**排期依据**：任务面复用 M1 建立的页面壳与配置存储；会话审计与采集线无依赖，双线并行完成。

**验收标准**：手动触发任务成功并进入历史，运行中重复触发被拒绝并提示；筛选、导出、统计结果与数据库对账一致；旧数据无损升级（历史记录身份为空显示匿名）。

### M3 · 9/15：周期采集试运行 + 数据导入正门

**交付内容**

1. **周期采集**：定时任务上线——企业新闻/官网产品重抓（每周）、论文元数据回填（每周）、教授主页与论文专利增量（每月）；全部限定夜间窗口执行，每轮设调用配额上限，连续失败自动熔断停跑。
2. **数据导入正门**（恢复网页入口，此前仅命令行）：
   - 页面上传企业/专利 Excel 表格：自动查重（同文件重复上传拒绝）、导入预检、企业数据自动进入富化流水线（产品/新闻/融资信息补全）；
   - 教授采集源管理：名单增删改查 + 触发抓取（全量/抽样/预览三种模式）。

**排期依据**：上传链在新环境下的适配是本计划最大的技术不确定点，安排在窗口前段（9/12 前）完成技术验证，验证通过后收尾界面。

**验收标准**：试运行模式——缩短触发间隔自动运行 ≥2 次 + 手动触发各 1 次均成功；一次企业表格从上传→富化完成→数据库产生增量全链走通；正式周/月节奏同步上线，长期运行表现延伸至交付后持续观察（任务面板可见）。

### M4 · 9/17：管理面收官 + 首次一键发布演练

**交付内容**

1. **管理面收官**：质量问题处理页（列表/解决/原始数据预览）；教授工作台动作（确认就绪/送审/标记重爬，与评审台流程衔接）；旧 React 管理前端正式退役——其全部能力已由新管理面承接，双前端并存问题就此收口。
2. **首次一键发布演练**："立即发布"按钮触发完整发布链——重建数据包 → 自举校验 → 7 个真实会话回放回归（确保新数据不引入回答错误）→ 备份门禁 → 原子切换 → 秒级重启 → 冒烟检查；**任一步失败自动回切旧版本**。窗口内完成一次真实发布和一次回滚演练。

**排期依据**：发布演练依赖 M1 的死锁修复与 M3 产生的采集增量；管理面收官依赖 M2 的任务面基建。

**验收标准**：真实发布端到端成功，问答服务中断不超过重启时长（秒级）；回滚演练成功恢复旧版本；旧前端下线后无引用残留、线上功能不受影响。

### M5 · 9/21：端到端验收 + 交付物

**交付内容**

1. **端到端验收**：走一次真实全链——采集产生新数据 → 一键发布新数据包 → 在对话入口检索到该新数据，验证闭环成立。
2. **交付物**：运维手册（日常巡检、发布、回滚、故障恢复流程）；客户现场迁移方案后半段素材（密钥与启动参数、首启冒烟、反向代理发布、守护与日常运维、回退预案）。

**验收标准**：端到端链路走通；文档与系统实际状态一致；数据恢复流程演练一次成功。

## 三、执行前提与风险（如实声明）

| # | 事项 | 说明 |
| --- | --- | --- |
| 1 | 双线并行是硬前提 | 全部工作量约 15–16 人日，两条线各一名执行者方可两周完成；单线不可行（备选：三周，或裁减质量问题页与审计统计两块） |
| 2 | 周期采集验收口径 | 两周窗口内等不到自然周/月周期，以试运行模式验收（缩短间隔自动触发 + 手动触发）；正式节奏同步上线，观察期延伸至交付后 |
| 3 | 最大技术不确定点 | 上传导入链在新运行环境下的适配，9/12 前出结论；若不通，降级方案为保留命令行导入 + 简化状态页，完整链路顺延 |
| 4 | 死锁修复超期预案 | 若超 2 个工作日，发布演练（M4 后半）顺延，其余交付不受影响 |
