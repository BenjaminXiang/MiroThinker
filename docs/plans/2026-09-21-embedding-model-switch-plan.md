# 换 embedding 模型迁移方案（v2 候选 · 2026-09-21 立项）

> 触发：用户提出把服务期 embedding 换成 `qwen3.7-text-embedding-flash`（第三方网关）。
> 本文只谈这一件事：为什么能/不能换、要准备什么、**以及"召回不退化"怎么证明**。
> 结论先行：**必须全量重建索引**，且**召回不退化是本方案的阻塞门**。

---

## 1. 现状与候选

| | 现状 | 候选 |
|---|---|---|
| 模型 | Qwen3-Embedding-8B | qwen3.7-text-embedding-flash |
| 维度 | **4096** | **1024** |
| 部署 | 自建 GPU 服务（`100.64.0.27:18005`，OpenAI 兼容） | 第三方网关 `maas.qianwenaiapi.com`（DashScope 原生形状） |
| 延迟 | 0.05 s（本机网络） | 0.28 s |
| 其它 | — | 轻量版（面向成本/吞吐）、TPM 1M / RPM 24K、128K 上下文 |

## 2. 探针结论（2026-09-21 实测，决定性）

用同一条探针串打两边：候选模型默认 **1024 维**；请求 `dimension: 4096` → **HTTP 400**；
把我们的 4096 维向量按 Matryoshka 截到前 1024 维并归一后与新模型比 → **cosine = -0.03（近似正交）**。

⇒ **不是同一个向量空间**。换它 = 换掉整个索引的语义空间 ⇒ **必须全量重建**；不存在"只改地址"的捷径
（对比：换一个**同模型**的新端点才是改地址，零重建——这正是 F2 + 身份探针存在的意义）。

**附带阻塞**：该入口是 DashScope 原生形状（`input: {texts: [...]}` / 响应 `output.embeddings[].embedding`），
而我们的构建期与服务期客户端是 OpenAI 兼容形状（`company/vectorizer.py:47-56`）。必须先解决形状。

## 3. 六步迁移

| 步 | 内容 | 量级 |
|---|---|---|
| 1 | **端点适配**：优先问到 OpenAI 兼容路径；否则写薄适配层（形状转换 + 错误映射）+ 测试 | 半天 |
| 2 | **身份三件套**：新 embedding bundle（`model_id` / `dimension=1024` / `base_url` + 重算 `content_sha256`）+ 更新 `_QWEN_EMBEDDING_BUNDLE_SHA256` / `_QWEN_EMBEDDING_DIMENSION`（`knowledge_build_isolated.py:266-275`） | 半天 |
| 3 | **全量重建**：51k 文档重嵌（受 TPM 1M 限制约 10–20 分钟）→ 新 `vector_matrix.npz`（1024 维，≈420 MB，比现在小 4 倍）→ 新包 → 封印 41 min → 切包 | 8 h + 41 min |
| 4 | **召回不退化验证**（§4，**阻塞门**） | 半天 |
| 5 | 凭据与合规：key 走受管密钥页；确认第三方网关的数据留存与稳定性承诺；**轮换已在聊天中出现过的 key** | — |
| 6 | 切换与回滚：F2 改地址 + 身份探针 → 重启；**旧包与旧 bundle 原样保留**，回滚 = 换回 | 分钟级 |

## 4. 召回不退化验收（本方案的阻塞门）

### 4.1 为什么不能只看 replay 门

replay 门 7/7 验证的是**行为契约**（话术、澄清、引用格式、多轮锚定）——**它不看召回本身**。
向量道退化会表现成"答案形状没变，但该召回的公司/论文变少了"，这种退化 replay 门完全抓不到。
所以召回必须单独、分层地测。

### 4.2 三层测什么

| 层 | 用例 | 指标（逐题记录） |
|---|---|---|
| **L1 检索层** | 测试集 25 轮 + 语义探针集（人工构造：只有向量道能服务的那类问题，如"做具身智能的公司""类似 X 的公司"） | ① GT 实体在候选中的命中；② **向量道候选数**；③ 本地/网络点数比例 |
| **L2 答案层** | 同一组用例 | ④ GT 实体出现在最终答案与引用卡的情况 |
| **L3 行为层** | replay 门 G1–G7 | ⑤ 契约不回归 |

### 4.3 基线必须"先取"

**换之前**用同一套脚本打当前实例（4096 维索引）→ 冻结成 JSON 作为基线；换之后同一脚本再打一次 → 逐题 diff。
基线一旦缺失，任何"没退化"的结论都不成立。
> 现有 `apps/admin-console/scripts/eval_recall*.py` 是 canonical-v2 **之前**的栈（走 Milvus+PG 老路径），**不能直接用**；
> canonical-v2 的 harness 正在建（含车道计数抓取与双跑 diff）。

### 4.4 判定规则（**已按实测噪声底重标定**，2026-09-21）

先给证据：**同一配置跑两遍**（各 37 轮、同包同索引同 case 序）——
**向量道 0/34 用例变化、中位数 61.0 → 61.0**（换模型真正会动的那个指标，**噪声为零**）；
但**答案层有 3 条"命中→未命中"在两次相同运行之间自行翻转**。根因查明：**基线那次是"网络道降级跑"**
（冷缓存、**17 次 provider 超时**），对照组热缓存、**0 次超时**。⇒ 按字面规则会把网络检索的天气当成召回退化，因此重标定：

| 规则 | 实测噪声 | 判定 |
|---|---|---|
| 有标注实体**同时**从候选集与答案里消失 | 0/18 | **FAIL**（这才是"召回退化"） |
| 有标注实体**只**从答案层消失 | 未出现 | **REVIEW**（更像 web 证据/合成形状问题） |
| 有标注实体**只**从候选层消失 | 7 增 0 失 | **REVIEW** |
| **概念类**关键点字符串 | 同配置两跑 **3 失 3 得** | 默认 **REVIEW**（`--strict-concepts` 可恢复为 FAIL） |
| 探针 GT 丢失 | 0 | **REVIEW**（不变） |
| 任一用例向量道候选数下降 **>50%** | 0/34 | **REVIEW**（全套件适用；**设 ≥8 的下限**，不在低位抖动上报警） |
| 向量道候选数**中位数下降 >30%** | 中位数完全相同 | **FAIL，照原样保留**（该指标零噪声，不会误报；但分布双峰，**逐用例列优先读**） |
| 概念字符串进候选层计分 | 7 个假"命中" | **移出判定**（只作参考信息） |

**降低噪声的便宜办法**（不改服务）：**换后跑两遍，只看第二遍**——第一遍把网络道缓存热起来
（实测 94 次实时 provider 调用 vs 323 次、超时 0 vs 17），而"有标注实体 0 翻转"正是在热缓存条件下成立的。
判定行现在还会带上 `[web timeouts=n]` 与锚定的网络道列，便于现场判断"这次翻的是召回还是网络"。

任一 **FAIL ⇒ 不切**；**REVIEW ⇒ 人工复核后再定**。

### 4.5 成本

25 轮 + ~15 探针 × 两遍 ≈ **80 轮问答**，每轮含常规 LLM 调用；需如实记账（配额）。

## 5. 收益 / 代价 / 风险

- **收益**：索引小 4 倍（1.68 GB → ≈420 MB）、数据面传输件显著变小、摆脱自建 GPU 服务；
- **代价**：一次 8 h 重建 + 全量重验；每轮查询 +0.28 s 远端延迟；第三方网关的稳定性与合规需确认；
- **风险**：flash 是轻量版 ⇒ **召回可能下降**（§4 就是为它设的门）；网关不可用 ⇒ F1 降级（语义召回丢失），可回滚。

## 6. 排期与依赖

**不阻塞 v1.1 发车**（v1.1 = 代码改动 + 41 min 重封）。建议顺序：
端点适配 + 新 bundle（半天）→ 基线已在手（见 §4.3）→ 重建（8 h）→ 复测与决策（半天）→ 切换。
