## 1. 为什么重写（诊断，均有代码证据）

`/admin` 是 W1→W2/W3→认证四次切片叠加的产物，**1093 行里 735 行是内联 JS**，四个结构性毛病：

1. **一个字段两条通道**：`extraction_endpoints.*` 既在"受管配置"表单里，又在"连接与密钥"表里——
   后者的保存路径还手写映射（`connectionKey === "embedding" ? …`）并从 `/secrets` 保存里
   偷偷再 PATCH 一次 `/config`；
1. **schema 三份拷贝**：服务端模型 → `EffectiveField`（无 label/kind/上下界）→ 页面手抄的
   `FIELD_SPECS`（新增字段被 `if (!field) return;` 静默吞掉）；
1. **保存=整表倾倒**：一次保存把 18 个字段全写成显式 override（默认值被冻结、env 不再穿透）；
   bool 永远写 true/false——**保存过一次就回不到"默认"**；空 int/空 text/bool 三种语义；
1. **一页四个关切且与 /main 重复**：状态表 vs /main；"Provider key 状态"表 vs 连接行；
   两个连通性机制（行内测试 + 全局"立即检查"）。

**根因**：服务端 `fields` 缺"展示信息"，逼得客户端自抄 schema；连接类字段没有归属规则，
于是长出了第二通道。

## 2. 设计规则（本片的验收内核）

1. **服务端字段目录是唯一真相**：`FIELD_CATALOG`（label/kind/group/order/上下界/consumer/默认值）
   随 `/config` 的 `fields` 下发；页面纯函数渲染，**删除本地白名单**；目录覆盖双向 fail-closed 测试。
1. **保存只提交脏字段**；值统一三态：**默认（显式 null，清除 override）/ 具体值 / 未触碰（不发）**；
   bool 用 默认·启用·停用 三态。
1. **配置·验证·展示同卡**（用户裁定）：
   - 卡片 1 采集与构建：collection.\* + 各域新鲜度/采集历史（显示）+ 闸门/最近运行状态；
   - 卡片 2 检索与回答：serving.\* + 来源徽章 + 运行期启用状态 + **\[测试 Rerank 连通性\]**（可用未保存值）；
   - 卡片 3 存储与保留：paths.\* + 三个库的计数/体积 + 磁盘余量 + 保留期预览；
   - 卡片 4 连接与密钥：5 张连接卡（运行期徽章/来源/掩码/密钥写入/端点模型/测试/保存本卡）；
   - 页首：生效横幅（N 项未保存 / 已保存需重启 + 可复制的重启命令）；页尾：只读快照折叠。
1. **一个字段一个入口**：端点字段只出现在连接卡；受管配置表单不再渲染它们。
1. **验证要诚实**：只有连接有主动探针；其它卡展示状态，不为按钮而造 dry-run。

## 3. 本轮不做

热加载（"保存→重启生效"语义不动）；前端框架（保持零依赖静态页）；新的 dry-run 探针；`/main` 布局改动。

## 4. 验收线（切 18188 后演示）

① 目录加行即出现（零客户端改动）；② 保存只写脏键、清默认可回退；③ bool 三态可回默认；
④ 端点单入口（配置表单里不再出现）；⑤ 每卡"测试（未保存值）→保存→横幅提示重启"链路；
⑥ 卡片 1/3 自带展示、无独立状态块、不与 /main 重复；⑦ 回滚演练（回退提交+重启）。
