## The pack's mount receipt

The sealer's `dogfood_open` writes the receipt as a side effect of opening the
fresh pack. It was first written as `verification: "full"` at 22:17:37
(`mount_seconds 299.19`); the independent fast-path open below then re-wrote it as
`verification: "receipt"` at 22:26:06 (`mount_seconds 119.052`). Both states bind
the same manifest:

```
schema_version        = canonical-v2-serving-mount-receipt-v1
pack_dir              = /var/tmp/mirothinker-data-v2/serving-pack-run16-v11
index_root            = /var/tmp/mirothinker-data-v2/index-v3-v2
release_id            = candidate-v2-20260916-r1
pack_manifest_sha256  = 588fdd9eb8f357484ad21f9a22ea0abe1bf3efa7f0b12862be8c2c514438276f
index_marker_sha256   = b6f78a3b1e28c280860a4210bfad286ef65090e758de5b876d7f639eefaa8373
```

A receipt only ever excuses checks for the manifest bytes it binds, so whichever
state travels with the pack is safe; a modified pack stops binding and the boot
falls back to full verification.

Two things run A proves beyond the timing:

1. The merged v1.1 reading code **reproduces the recorded request hashes of the

2. Serving the old pack under v1.1 code would pay the replay on every boot; that
   is the ~165 s this re-seal removes (284.4 s → 119.9 s for the same code and the
   same content, and the earlier boot-level measurement of the same effect was
   421 s → 291 s for the whole boot).
